## 2. P4 之前做了什么（P0–P3）

这四步是把算法装进代码，不是论文主表。

### P0 环境

固定工作区、配置入口、随机源和测试能跑通。没有这一步，后面所有 seed 对不上。

### P1 Synthetic oracle

按 PDF 用 seed 2026 冻结 16 维、4 分量 GMM，再加非线性 warp，得到参考测度 \(Q_0\)。实现：任意两坐标 panel 的解析条件高斯混合、倾斜抽样、特征映射 \(\phi\)、配分、\(\mu_\beta\)、Fisher \(F\)、panel 信息 \(I_S\)、目标 KL。这一阶段 **不用 VAEAC**，条件律是精确的。

**做到哪：** 评估原语齐了。后面风险比的分母 \(\varphi\) 从这里来。

### P2 三种政策

在 exact oracle 上实现：

- Uniform SQD：120 个 panel 均分；
- A-OSQD：Jang 的 A-optimal split-questionnaire；
- oracle RR-GID：用 \(F\)、\(I_S\) 做 Frank–Wolfe，得到 \(p^\star\)。

同时实现成本感知取整和预算账。三个政策能吐出可审计的分配。

### P3 整条 Algorithm 2

把 PDF 的 Pilot–Design–Update 串起来：平衡 pilot、Horvitz–Thompson 矩、反解 \(\widetilde\beta\)、交叉完备估 \(I_S\)、一次设计、主实验、\(J\) 步 Fisher scoring，投影回 \(\Theta\)。

**做到哪：** 固定 seed 的小预算玩具能从头跑到 \(\widehat\beta\)。大预算下是否一阶有效，是 P4 的事。P3 过了才进入 P4。

## 3. P4 正在做什么

规划里的正式 P4 是：Uniform / A-OSQD / oracle RR-GID，预算 \(\{2000,4000,8000,16000,32000\}\)，每格 **50** 次，看 \(B\cdot\mathrm{KL}\) 是否靠近 \(\varphi/2\)。

正式格子开跑之前，P4 先走诊断阶梯，一次只加一层：

**G0 → G1 → G2 → G3**（已过）→ G4（先停，待审核）→ 正式 3×5×50（先停，待审核）。

Gold 基线已冻结：\(\varphi=67.216\)，\(\varphi/2=33.608\)，独立重建相对差 1.87%（门 2%）。oracle 分配下主设计比为 1。后面 G0–G3 都读同一份 artifact。

## 4. 诊断阶梯怎么读

阶梯的目的是 **一次只加一层**。共同的工程门：oracle 时设计比 = 1；H 用 Cholesky；raw KL 不低于容差；**终端风险比均值 < 10**。门 10 只排除爆炸，不是效率 1。

风险比：

\[
\frac{B\cdot\mathrm{KL}(\beta^\star\|\widehat\beta)}{\varphi/2},\qquad \varphi/2=33.6078.
\]

| 阶梯 | 这一层新加入的东西 | 状态 |
| --- | --- | --- |
| G0 | 从真值 \(\beta^\star\) 起步，无 pilot | **已过** |
| G1 | 真实 pilot + gold \(H\) + gold score | **已过**（带步长帽） |
| G2 | 把 gold \(H\) 换成有限样本估计 \(H\) | **已过** |
| G3 | 再把 gold score 换成有限 score | **已过**（QMC 与 rejection） |
| G4 | 再用 \(\widehat p(\widetilde\beta)\) 换掉 \(p^\star\) | **先停，待审核后再跑** |

G1–G3 全部锁死 oracle 分配。\(B=8000\) 时 \(J=0\)（还没 Newton）的风险比均值在 G1–G3 都是 **52.92**，逐 replication 相同：比的是「同一个很远的起点能不能拉回来」。

## 6. G1：真实 pilot + 全 gold 算子（已过）

## 8. G3：再换成有限 score（两门都过，当前停在这里）

**这一层新加入什么。** \(H\) 继续用 G2 的估计。Score 不再用 gold，分别换成：

1. **G3 QMC：** 固定阶 QMC，`qmc_order=10`；
2. **G3 rejection：** 有限 \(L_U=\lceil 32\log_2(B+1)\rceil=415\) 的拒绝抽样。

## 10. 根据 G1–G3，对 G4 和正式 P4 的判断

**判断：G4 和正式 P4 大概率能跑成功。** 现在先停下来审核，而不是因为阶梯失败。

依据：

- G0 排除了反号和常数错误。
- G1 说明远 pilot 加带帽 Newton 能进盆，终端风险比约 1。
- G2 说明换成估计 \(H\) 仍进盆（终端 1.91，20/20 < 10）。
- G3 说明换成正式会用的有限 score 仍进盆（QMC 1.46，rejection 1.27，最大都低于 4）。
- 正式 P4 的 oracle RR-GID 就是 G3 这条链，只是预算从 1 档变成 5 档、重复从 20 变成 50、再加 Uniform / A-OSQD。G4 只是在同一条 scoring 链上把 \(p^\star\) 换成 \(\widehat p(\widetilde\beta)\)，多一步设计，不是另一套估计器。

因此：**数值上大概率不会再出现 G1 无帽那种爆炸；估计器和近似层已经过了灾难门。** 正式效率曲线是否漂亮、Uniform / A-OSQD 相对 oracle 差多少，仍要正式格子才能下结论，但「跑不完 / 跑爆」不是当前的主风险。

**当前的主风险是墙时，不是过不过门。** G3 rejection 单档 \(B=8000\)、20 次就要 1.6 天，最慢一条 13.7 小时。G4 还要在远 pilot 上扫 120 个 panel，只会更长。正式 3×5×50 若继续拒绝抽样，按天到按月计；走 QMC 大规模路径则大约数天到一周。所以 **先审核路径、\(J\)、是否先做性能重构，再决定开 G4 还是直接开正式格子**，避免一开就锁在几十天的拒绝抽样上。

| 后面 | 成功把握 | 为什么先停 |
| --- | --- | --- |
| G4 plugin | 大概率能过灾难门 | 同一套估计器，只多设计一步；但比 G3 更肥尾，要先确认值得花这些天 |
| 正式 P4 50 次 | 大概率能跑完且 oracle 不爆炸 | 格子是 G3 的几十倍；拒绝抽样可能要一到三个月，QMC 则短得多，需要审核选哪条 |
