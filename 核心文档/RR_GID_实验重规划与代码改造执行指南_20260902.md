**版本：2026-09-02**  
**适用仓库：`https://github.com/15628925702/RR` 当前 `main` 快照**  
**目标：把实验从“理论条件逐层诊断”改成“一个主指标 + 两个机制问题 + 一个真实数据验证”，并把单个实验的墙时控制在几小时内。**

---

## 0. 先做出的决定

从现在开始，不再把 G0–G4 当作论文实验，也不再继续扩展 rejection、\(L_U\)、\(H\)-growth、步数、步长、pilot 等诊断矩阵。

论文实验只回答三个问题：

1. **主问题：** 在固定 measurement budget 下，RR-GID 是否降低完整 target distribution 的估计误差？
2. **机制问题 A：** 优势是否来自 nonlinear conditional information，而不是普通 covariance information？
3. **机制问题 B：** frozen generator 是否能跨 campaign 复用，从而获得更好的 risk–compute frontier？

真实数据只验证上述结论在真实 dependence 和 drift 下是否仍然成立。

开发阶段保留一个非常小的数值校准，用于证明快速 QMC 后端足够接近高精度 oracle。除此之外，不再跑 G0–G4、rejection 大规模路径或多套 numerical gate。

# 1. 论文实验的最终结构

## 1.1 统一的核心任务

给定固定 target measurement budget \(B\)，比较不同 panel allocation policy 收集数据后，对 target full distribution 的恢复误差。

论文层面的统一 primary quantity 是：

\[
\mathcal L_{\mathrm{dist}}
=
\text{full-distribution estimation loss}.
\]

在不同 setting 中使用与 ground truth 匹配的具体形式：

### Synthetic

\[
R_{\mathrm{risk}}
=
\frac{
B\,\mathrm{KL}(Q_{\beta^\star}\Vert Q_{\widehat\beta})
}{
C^\star
},
\qquad
C^\star
=
\frac12\Phi_{\beta^\star}(p^\star).
\]

解释：

- 越低越好；
- \(R_{\mathrm{risk}}=1\) 是 oracle first-order efficiency reference；
- 所有 budget 可以画在同一纵轴上；
- 这是正文唯一的 synthetic primary metric。

### Real data

真实 drift 未必严格满足 exponential tilt，因此使用 family-projection loss：

\[
D_{\widehat A}(\widehat\beta,\beta^\dagger)
=
\widehat A(\widehat\beta)
-
\widehat A(\beta^\dagger)
-
(\widehat\beta-\beta^\dagger)^\top
\nabla\widehat A(\beta^\dagger).
\]

这是正文真实数据的 primary metric。

### Secondary diagnostics

只保留两个：

1. design ratio
   \[
   R_{\mathrm{design}}
   =
   \frac{\Phi_{\beta^\star}(\widehat p)}
        {\Phi_{\beta^\star}(p^\star)};
   \]
2. method-specific compute time。

它们只用于解释机制，不作为第二组主结果。


随机选择 20 个 panels、5 个 \(\beta\)：

\[
\left\|
M_{\rm gold}^{-1/2}
(\widehat M-M_{\rm gold})
M_{\rm gold}^{-1/2}


# 4. Oracle 在新计划中的角色

高精度 oracle 只做三件事：

1. 一次性冻结
   \[
   p^\star,\quad \Phi(p^\star),\quad C^\star;
   \]
2. 校准 fast cached QMC backend；
3. 提供 synthetic 的水平 reference line。

它不再作为每个 replication 的在线实现。

Bulk experiments 使用：

\[
Q_0(\cdot\mid x_S)
\text{ 的固定 QMC basis}
+
\beta\text{-dependent reweighting}.
\]

这仍然利用真实 conditional structure，但不在每个 Newton step 重新生成相同的 conditional nodes。

论文中应写：

> High-precision conditional integration is used only to calibrate the numerical backend. Large-scale experiments use a validated fixed-order cached QMC approximation.

不要把 bulk backend 称为 “exact oracle score”。

# 5. 速度重构的核心数学结构

对任意 target observation \(x_S\)，

\[
E_\beta[\phi(X)\mid X_S=x_S]
=
\frac{
E_{Q_0}\left[
\phi(X)e^{\beta^\top\phi(X)}
\mid X_S=x_S
\right]
}{
E_{Q_0}\left[
e^{\beta^\top\phi(X)}
\mid X_S=x_S
\right]
}.
\]

因此 \(Q_0(\cdot\mid x_S)\) 的 nodes 与 \(\beta\) 无关。

第一次为该 observation 生成：

\[
X^{(1)},\ldots,X^{(K)}
\sim Q_0(\cdot\mid x_S),
\]

并缓存：

\[
\phi^{(1)},\ldots,\phi^{(K)}.
\]

之后每个 scoring step 只计算：

\[
w_k(\beta)
\propto
e^{\beta^\top\phi^{(k)}},
\qquad
\widehat m_{\beta,S}(x_S)
=
\sum_k w_k(\beta)\phi^{(k)}.
\]

这把当前路径：

```text
每个 beta
  -> 条件高斯构造
  -> QMC normals
  -> warp
  -> feature map
  -> tilt
  -> reduce
```

改为：

```text
每个 observation 一次
  -> 条件 basis + feature cache

每个 beta
  -> logits
  -> logsumexp
  -> weighted reduction
```

同样的逻辑用于 panel information。

# 6. 新的 fast conditional backend

新增模块：

```text
src/rr_gid_cn/conditional_backend.py
```

建议提供三个对象。

## 6.1 `ReferenceMomentCache`

保存：

```text
phi_reference
phi_reference_eval
A_beta_true
mu_beta_true
F_beta_true
```

接口：

```text
moments(beta) -> mu_beta, F_beta
log_partition(beta) -> A_beta
kl(beta_true, beta_hat) -> scalar
```

所有 feature map 只在 artifact build 阶段计算一次。

## 6.2 `ConditionalFeatureBasis`

对一组按 panel 分组的 observations 保存：

```text
panel
observed_rows
component_log_posterior
phi_nodes
qmc_order
seed
dtype
```

其中建议：

```text
phi_nodes shape:
[n_rows, n_components, n_nodes, r]
```

接口：

```text
conditional_mean(beta)
conditional_mean_and_cov(beta)
```

不允许接口内部再次调用 Gaussian conditional sampling。

## 6.3 `PanelInformationBasis`

固定一批 \(Q_0\) outer rows，并为每个 candidate panel 缓存两套独立 conditional QMC bases：

```text
outer_phi
outer_panel_values
basis_a
basis_b
```

每个 \(\beta\) 下：

1. 用 \(e^{\beta^\top\phi}\) 对 outer rows reweight；
2. 分别计算两套 conditional means；
3. 形成 weighted cross-covariance；
4. PSD projection；
5. 返回 \(\widehat I_S(\beta)\)。

这仍然对应 cross-completion，只是把 base draws 固定并复用。

## 7.1 `src/rr_gid_cn/synthetic_oracle.py`

### 必改 1：增加 observation-specific feature cache

当前只缓存 panel Gaussian 参数和 Sobol normals，没有缓存 observation-specific conditional feature nodes。

增加：

```text
build_conditional_feature_basis(...)
evaluate_conditional_basis(beta, basis)
```

bulk path 不再直接调用 `tilted_conditional_mean_qmc()`。

### 必改 2：固定 QMC basis 跨 scoring steps 复用

同一 observation、panel、seed 的 nodes 只生成一次。

### 必改 3：只生成 feature-relevant missing coordinates

当前 feature map 只依赖前 12 个坐标。不要继续生成完整 complement 的全部 Sobol dimensions。

### 必改 4：hot path 改为 FP32

当前 CUDA QMC/rejection tensor 使用 `torch.float64`。RTX 4080 上这会非常慢。

改为：

```text
Gaussian transform / warp / phi / logits / normalized weights: float32
final conditional moments: cast to float64
H / F / KL / linear solve: float64
```

必须用 calibration 证明 FP32 与 FP64 的误差低于 QMC 误差。

### 必改 5：移除 hot-loop `gc.collect()` / `torch.cuda.empty_cache()`

只允许：

- 捕获 OOM 后；
- 一个完整 replication 结束后；
- 显式 cache eviction 时。

普通 chunk 之间依赖 PyTorch caching allocator。

### 必改 6：rejection 不再进入 bulk API

保留函数用于 oracle sanity check，但默认 runner 不暴露 `rejection` 选项。

### 必改 7：缓存 posterior component probabilities

\[
Q_0(K=k\mid X_S=x_S)
\]

与 \(\beta\) 无关。basis build 时计算并缓存。

### 建议改 8：预分配 workspace

避免每个 panel/chunk 反复创建：

```text
z
x
phi
logits
numerator
denominator
```

### 建议改 9：记录真实 workload

计数至少包含：

```text
feature_nodes_built
feature_nodes_reweighted
component_nodes
cache_hit
cache_miss
bytes_cached
```

# 10. 并行与硬件使用

## 单卡

- 一个 Python process；
- `OMP_NUM_THREADS=1`；
- `MKL_NUM_THREADS=1`；
- `OPENBLAS_NUM_THREADS=1`；
- 不允许同一 GPU 两个进程争用；
- policy 顺序执行，复用 shared caches；
- replication 之间并行，而不是 panel 之间启动多个进程。

## 多卡

每张 GPU 一个 worker，每个 worker处理不同 replication shard。

禁止：

```text
2 processes / GPU
4 BLAS threads / process
```

GPU utilization 不是目标；目标是 completed replications/hour。

# 13. 与理论的一致性

以下加速不改变理论对象：

1. 缓存 \(Q_0(\cdot\mid x_S)\) nodes；
2. scoring steps 之间复用同一 reference nodes；
3. 对不同 \(\beta\) 只重算 exponential-tilt weights；
4. 用两套独立 Sobol scrambles 做 cross-completion；
5. reference feature matrix 预计算；
6. Cholesky 替代 pseudoinverse；
7. common random numbers across methods；
8. 更大的 sublinear pilot；
9. 任意固定有限 \(J\)。

需要在论文实现部分说明：

- high-precision oracle 只用于 calibration；
- bulk uses fixed-order cached QMC；
- QMC order 在 main metric 运行前冻结；
- FP32 hot path 经过 FP64 校准；
- fixed numerical approximation 不被称为 “exact score”。

不要在未补理论前把 final estimator 改成完全不同的 surrogate objective。当前计划仍实现原 conditional-score/Fisher-scoring 结构。

# 16. 最关键的实施优先级

按照收益排序：

1. **缓存 observation-specific conditional feature nodes；**
2. **缓存 panel-information conditional bases；**
3. **跨 \(\beta\) 只 reweight；**
4. **shared pilot 移出 policy loop；**
5. **step-0 information reuse；**
6. **FP32 hot path；**
7. **score/information QMC order 分开；**
8. **去掉 rejection bulk；**
9. **统一 runner 和 result schema；**
10. 最后才考虑 Frank–Wolfe 或小型线性代数优化。

现在最不应该做的是继续跑 rejection、继续扩 G4、继续增加 \(J/L_U/H\) 诊断。  
现在最应该做的是把 conditional expectation 从“每步重新积分”改成“base conditional basis 一次构造、后续快速重加权”。
